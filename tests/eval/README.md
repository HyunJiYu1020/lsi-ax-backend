# AI 판단 평가 세트 (eval)

`tests/` 아래 나머지 테스트가 지키는 건 **배선**이다 — 번역 캐시가 맞게 동작하나,
쓰기 도구가 승인을 거치나, 프롬프트에 지침 문장이 들어가나. LLM은 전부 가짜로 바꿔 놓는다
(`test_reason_translate.py` 주석: "번역 품질이 아니다").

여기서 재는 건 **판단 품질**이다: 말 한마디에 모델이 **어떤 도구를 고르나**, 사유 초안이
**지침을 지키나**, 숫자를 **지어내지 않나**. 프롬프트(`chat_prompts.py`)를 고쳤을 때
그게 나빠졌는지 알 방법이 지금까지 없었다 — 사람이 챗봇을 눌러 보는 것 말고는.

## 돌리는 법

```bash
RUN_EVAL=1 .venv/bin/python -m pytest tests/eval -v        # 전체
RUN_EVAL=1 .venv/bin/python -m pytest tests/eval -v -k anomaly
.venv/bin/python -m pytest tests/eval                      # 게이트에 막혀 전부 skip
```

**기본이 skip인 이유**: 실제 Gemini를 부른다. 돈이 들고, 네트워크가 필요하고, 같은 입력에
항상 같은 답이 오지 않는다. 평소 `pytest`에 섞이면 "가끔 빨간" 테스트가 되고, 그러면
아무도 빨간색을 안 믿게 된다. 프롬프트·도구 설명·지침 규칙을 건드렸을 때만 손으로 돌린다.

`GEMINI_API_KEY`가 없으면 LLM이 필요한 항목만 skip된다. 전표 매칭 회귀(`suggest_lab`)는
규칙 기반이라 키 없이도 돈다.

## 왜 "시나리오 파일"인가

판정 기준을 YAML에 두면 **업무를 아는 사람이 테스트를 늘릴 수 있다**. "이렇게 말했을 때
이 도구가 불려야 한다"는 건 개발자보다 담당자가 더 잘 안다. 파이썬 쪽은 러너 하나뿐이고,
늘어나는 건 `scenarios/*.yaml`의 행이다.

## 판정 방식 — 통과/실패를 가르는 선

흐릿한 자연어를 통째로 비교하지 않는다. 기계가 확실히 가를 수 있는 것만 본다:

| 키 | 뜻 |
|---|---|
| `expect.tool` | 이 쓰기 도구가 `pending`으로 올라와야 한다 |
| `expect.args` | 그 도구 인자가 이 값이어야 한다(부분 일치 — 적은 키만 본다) |
| `expect.args_absent` | 사용자가 말하지 않은 인자를 채워 넣지 않았다 |
| `expect.no_write_tool` | 저장하려 들지 않아야 한다(= 물어보거나 조회만) |
| `expect.asks_user` | 도구를 부르지 않고 사람에게 되물어야 한다 |
| `expect.reply_has` / `reply_lacks` | 답변에 이 말이 들어/안 들어가야 한다 |
| `expect.max_lines` | 초안 줄 수 상한(지침 "3줄 이내"가 지켜지나) |
| `expect.only_numbers` | 초안에 이 숫자들 말고 **다른 숫자가 나오면 실패**(지어내기 탐지) |

`expect.args`를 부분 일치로 두는 게 중요하다. 전체 비교로 두면 도구에 인자가 하나 늘 때마다
시나리오를 전부 고쳐야 하고, 그러면 아무도 안 고치고 세트가 썩는다.

## 골든 데이터 — 정답지는 이미 DB에 있다

사람이 손으로 만든 정답지는 금방 낡는다. 이 저장소에는 **담당자가 AI를 고친 기록**이 그대로
쌓여 있어서, 그게 정답지다:

| 테이블 | 무엇이 정답지인가 |
|---|---|
| `variance_reasons` | `ai_draft` ≠ `reason_text`인 행 = 담당자가 **실제로 고친** 초안 (`past_draft_edits`) |
| `close_voucher_maps` | `decided_by='user'` = **AI 추천이 틀려서** 사람이 바로잡은 전표 |

`test_golden_regression.py`가 이걸 다시 먹여서 "지금 코드로도 같은 실수를 하나"를 본다.
데이터가 없으면 skip한다 — 빈 DB에서 초록불이 뜨면 그게 더 위험하다.

**숫자를 통과 조건으로 쓸 때의 한계**: 사유 초안은 "담당자 문장과 얼마나 닮았나"로 재는데,
닮지 않은 게 더 나은 문장일 수도 있다. 그래서 하한만 둔다(크게 망가진 것만 잡는다).
